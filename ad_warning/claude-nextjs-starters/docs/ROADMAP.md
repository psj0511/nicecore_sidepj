# 광고 성과 이상 감지 시스템 개발 로드맵

Notion에 올린 광고 성과 CSV에서 이상 징후를 자동으로 찾아 이슈로 등록하고, Notion 티켓으로 넘겨 대응 누락을 막는 MVP

## 개요

광고 성과 이상 감지 시스템은 **퍼포먼스 마케팅 운영 담당자와 팀장**을 위한 이상 징후 자동 탐지·대응 도구로 다음 기능을 제공합니다:

- **Notion 실시간 연동 (F002, F003)**: Notion 부모 페이지 하위의 광고 성과 데이터베이스(CSV를 가져온 것)를 조회 시점에 직접 읽어 검증하고 연결·검증 상태를 보여줌(복사·저장·동기화 이력 없음, 2분 캐시). 앱 내 CSV 직접 업로드는 없음
- **이상 감지 및 이슈 자동 생성 (F004, F005)**: 규칙 R1~R6을 설정 가능한 임계값으로 적용해 위반 건을 이슈로 생성 (R7·R8은 자리만 제공)
- **이슈 관리 및 Notion 티켓 (F006~F009)**: 이슈 조회·상태 관리·메모, Notion 데이터베이스로 티켓 생성
- **성과·이슈 대시보드 (F001)**: 핵심 지표와 미해결 이슈를 한눈에 확인

> **데이터 원칙**: 앱 전용 DB(Supabase)는 쓰지 않고 Notion을 단일 저장소로 사용한다. 성과 지표는 복사하지 않고 원본 Notion DB를 실시간 조회하며, 규칙·이슈는 부모 페이지 하위 `[AD] 감지 규칙`, `[AD] 이슈` DB에 저장한다.

> MVP 제외: 앱 내 CSV 직접 업로드, 웹훅·주기 실행 기반 자동 감지, 매체 API 자동 수집, R7·R8 실제 평가, 알림 발송, 인증/권한, 담당자 지정·댓글, 리포트 내보내기

## 개발 워크플로우

1. **작업 계획**

- 기존 코드베이스를 학습하고 현재 상태를 파악
- 새로운 작업을 포함하도록 `ROADMAP.md` 업데이트
- 우선순위 작업은 마지막 완료된 작업 다음에 삽입

2. **작업 생성**

- 기존 코드베이스를 학습하고 현재 상태를 파악
- `/tasks` 디렉토리에 새 작업 파일 생성
- 명명 형식: `XXX-description.md` (예: `001-setup.md`)
- 고수준 명세서, 관련 파일, 수락 기준, 구현 단계 포함
- **API/비즈니스 로직 작업 시 "## 테스트 체크리스트" 섹션 필수 포함 (Playwright MCP 테스트 시나리오 작성)**
- 예시를 위해 `/tasks` 디렉토리의 마지막 완료된 작업 참조. 예를 들어, 현재 작업이 `012`라면 `011`과 `010`을 예시로 참조.
- 이러한 예시들은 완료된 작업이므로 내용이 완료된 작업의 최종 상태를 반영함 (체크된 박스와 변경 사항 요약). 새 작업의 경우, 문서에는 빈 박스와 변경 사항 요약이 없어야 함. 초기 상태의 샘플로 `000-sample.md` 참조.

3. **작업 구현**

- 작업 파일의 명세서를 따름
- 기능과 기능성 구현
- **API 연동 및 비즈니스 로직 구현 시 Playwright MCP로 테스트 수행 필수**
- 각 단계 후 작업 파일 내 단계 진행 상황 업데이트
- 구현 완료 후 Playwright MCP를 사용한 E2E 테스트 실행
- 테스트 통과 확인 후 다음 단계로 진행
- 각 단계 완료 후 중단하고 추가 지시를 기다림
- 작업 완료 전 `npm run check-all`, `npm run build` 통과 확인

4. **로드맵 업데이트**

- 로드맵에서 완료된 작업을 ✅로 표시

## 개발 원칙

- **규칙 기준 문서**: `docs/detection-rules.md`. 규칙 구현·수정 전 반드시 먼저 읽는다.
- **임계값 분리**: 임계값·목표값은 하드코딩하지 않고 `rules.config.ts` 기본값 + Notion `[AD] 감지 규칙` DB(`DetectionRule`) 설정으로 분리한다.
- **순수 함수 + 테스트**: 규칙은 `src/lib/detection/rules/`에 순수 함수로 작성하고 규칙마다 단위 테스트를 둔다.
- **명세 외 규칙 금지**: 명세에 없는 규칙·임계값은 임의 추가하지 않고 먼저 제안한다.
- **인증 없음**: MVP는 로그인 없이 단일 워크스페이스로 동작한다. 단, Notion 토큰은 서버 측(환경 변수)에서만 다루고 클라이언트에 노출하지 않는다.
- **실시간 조회**: 성과 데이터는 복사·저장하지 않고 `src/lib/notion/sources.ts`로 조회 시점에 읽는다(2분 캐시, 수동 새로고침). 앱 데이터 DB(`[AD] …`)는 성과 DB 탐색에서 반드시 제외한다(`isStoreTitle`).

### Phase 3: 핵심 기능 구현

> ⚠️ **실시간 연동 + Notion 단일 저장소**: Supabase와 동기화(가져와 저장)·동기화 이력·삭제는 폐지했다. 성과 데이터는 `src/lib/notion/sources.ts`가 조회 시점에 직접 읽고(캐시 2분, `/sources` 화면의 새로고침으로 즉시 갱신), 규칙·이슈는 Notion 하위 DB에 저장한다.

- **Task 006: Notion 데이터 액세스 계층 구축** ✅ (구 "Supabase 연동")
  - Supabase를 제거하고 Notion 단일 저장소로 전환: `src/lib/notion/`(client, props, pages, store, sources), `src/lib/repositories/`(issues, rules)
  - 부모 페이지 하위에 `[AD] 감지 규칙`, `[AD] 이슈` DB를 자동 생성하고 R1~R8 기본 규칙을 시드 (R7·R8은 `stage=2`, 비활성). 성과 DB 탐색에서는 `isStoreTitle`로 제외
  - 환경 변수(`NOTION_TOKEN`, `NOTION_PARENT_PAGE_ID`, `NOTION_DATABASE_ID`)를 Zod로 검증, 토큰은 서버 전용
  - 이슈·규칙 조회·수정은 앱 데이터 DB에 속한 페이지만 허용 (임의 페이지 ID 접근 차단)
  - 검증 완료: 실제 Notion 워크스페이스에서 `/rules`(임계값 수정·활성 토글·R7 차단), `/issues`(상태 변경·메모 저장, 새로고침 후 유지) CRUD 및 영속성 확인 (Playwright)

- **Task 007: Notion 실시간 연동·검증·연결 상태 화면 구현 (F002, F003)** ✅
  - 부모 페이지 하위 데이터베이스 탐색: `blocks.children.list`로 `child_database` 수집(`has_more` 페이지네이션), 티켓·앱 데이터 DB 제외. 하위 페이지 재귀 탐색은 미구현(현재는 부모 페이지 직속만)
  - 행 조회: `dataSources.query` 전 페이지 순회, 속성 값 변환 및 Zod 검증(필수 속성, 날짜 형식, 숫자 — CSV로 텍스트가 된 숫자 포함, 채널 값). 필수 속성이 없으면 DB 단위로 1건만 보고
  - 검증 오류 행은 감지에서 제외하고 행 번호·사유를 `/sources`에 표시
  - 2분 캐시(`unstable_cache`) + "지금 새로고침"(태그 재검증). DB 하나가 실패해도 나머지는 계속 표시
  - Notion 속성 서식 안내(필수 속성명 목록) 제공
  - 구글 Ads·네이버 검색광고 원본 컬럼명 별칭 매핑(`METRIC_PROPERTY_ALIASES`): 보고일/일별, 매체, 비용/총비용, 클릭수, 노출수, 전환수/총전환수, 전환 가치/총전환매출액. 실연동 확인: 구글 7/7행, 네이버 9/9행 정상

  - 검증 완료(Playwright 스크립트, 실제 Notion): 정상 조회 7/7·9/9행, 테스트 행 추가 후 새로고침 시 행 번호와 함께 날짜·채널·숫자 오류 표시, 삭제 후 새로고침 시 오류 사라짐, 미연동 안내 및 설정 화면 이동. 필수 속성 누락은 별칭 매핑 전 실데이터로 확인. `NOTION_TOKEN=`처럼 빈 값이면 500이 나던 문제는 빈 값을 미설정으로 처리하도록 수정
