# 광고 성과 이상 감지 및 운영 이슈 자동화 시스템 MVP PRD

## 🎯 핵심 정보

**목적**: 광고 성과 데이터에서 이상 징후를 자동으로 찾아 이슈로 등록하고, Notion 티켓으로 넘겨 대응 누락을 막는다.
**사용자**: 광고 성과를 매일 점검하는 퍼포먼스 마케팅 운영 담당자와 팀장

## 🚶 사용자 여정

```
1. 대시보드 페이지
   ↓ 데이터가 없거나 최신화가 필요할 때 "데이터 수집 관리" 메뉴 선택

2. 데이터 수집 관리 페이지
   ↓ CSV 업로드 → 검증 → 저장 → 활성 규칙으로 이상 감지 자동 실행

   [검증 실패] → 오류 행 안내 → 파일 수정 후 재업로드
   [검증 성공] → 대시보드 페이지로 이동 (감지 결과 반영)
   ↓

3. 이슈 목록 페이지
   ↓ 이슈 선택

4. 이슈 상세 페이지
   ↓ 상태 변경 / "Notion 티켓 생성"

   [Notion 미연동] → Notion 연동 설정 페이지 → 이슈 상세 페이지로 복귀
   [Notion 연동됨] → 티켓 생성 완료, 티켓 링크 표시

5. 감지 규칙 관리 페이지 (필요 시)
   ↓ 규칙별 임계값 수정·활성/비활성 (R1~R6 적용, R7·R8은 자리만) → 다음 업로드부터 적용
```

## ⚡ 기능 명세

### 1. MVP 핵심 기능

| ID | 기능명 | 설명 | MVP 필수 이유 | 관련 페이지 |
|----|--------|------|-------------|------------|
| **F001** | 성과·이슈 현황 대시보드 | 기간별 핵심 지표(광고비, 클릭, 전환, ROAS)와 미해결 이슈 수, 최근 이슈를 요약 표시 | 담당자·팀장이 한눈에 상태 파악 | 대시보드 페이지 |
| **F002** | CSV 업로드 | 광고 성과 CSV 파일을 업로드하고 형식(필수 컬럼, 날짜·숫자 값)을 검증해 저장 | 데이터 수집의 유일한 입구 | 데이터 수집 관리 페이지 |
| **F003** | 업로드 이력 관리 | 업로드 파일별 상태·행 수·오류 내역 조회, 잘못 올린 업로드 삭제 | 잘못된 데이터 정정 | 데이터 수집 관리 페이지 |
| **F004** | 감지 규칙 관리 | 규칙 R1~R8 목록 조회, 규칙별 임계값 수정, R5 목표값(CPA/ROAS 기준) 설정, 활성/비활성 전환. R7·R8은 규칙 정의와 설정 자리만 제공하고 2단계 데이터가 들어오면 평가 | 이상 판단 기준 설정 | 감지 규칙 관리 페이지 |
| **F005** | 이상 감지 및 이슈 생성 | 업로드 완료 시 활성 규칙(1단계 R1~R6)을 공통 원칙에 따라 적용해 위반 건을 이슈로 자동 생성. 비교 기준(데이터 7일 미만 전일, 7일 이상 직전 7일 평균), 최소 규모 필터(기준일 비용 100,000원 미만 제외), 평가 단위(구글 캠페인, 네이버 광고그룹), 감지 키(규칙, 대상, 날짜) 중복 방지, 주말·공휴일 완화 적용 | 시스템의 핵심 가치 | 데이터 수집 관리 페이지, 감지 규칙 관리 페이지 |
| **F006** | 이슈 목록 조회 | 이슈를 상태·심각도·기간으로 필터링해 목록 조회 | 처리할 이슈 파악 | 이슈 목록 페이지, 대시보드 페이지 |
| **F007** | 이슈 상세 및 상태 관리 | 감지 근거(규칙, 기준값, 실제값, 대상 캠페인) 확인, 상태 변경(신규·진행중·해결·무시), 메모 작성 | 이슈 대응 이력 관리 | 이슈 상세 페이지 |
| **F008** | Notion 연동 설정 | Notion 연동 정보(토큰, 대상 데이터베이스) 저장 및 연결 확인 | 티켓 생성의 선행 조건 | Notion 연동 설정 페이지 |
| **F009** | 이슈→Notion 티켓 생성 | 이슈 내용을 Notion 데이터베이스에 티켓으로 생성하고 링크를 이슈에 저장 (이미 생성된 이슈는 재생성 방지) | 이슈를 팀 업무 흐름으로 전달 | 이슈 상세 페이지 |

### 2. 감지 규칙 정의

**공통 원칙**

- 비교 기준: 데이터 7일 미만이면 전일, 7일 이상이면 직전 7일 평균
- 최소 규모 필터: 기준일 비용이 100,000원 미만인 대상은 평가 제외
- 평가 단위: 구글 = 캠페인, 네이버 = 광고그룹
- 중복 방지: 동일 (규칙, 대상, 날짜)는 이슈 1건만 생성 (감지 키)
- 주말·공휴일 완화: 대상일이 주말·공휴일이면 R5와 전환 감소 계열은 심각도를 한 단계 낮추고 "주말·공휴일 가능성" 안내를 붙임

**규칙 목록**

| ID | 유형 | 조건 | 심각도 | 의심 원인 | 지원 |
|---|---|---|---|---|---|
| R1 | 비용 급증 | 비용 변화율 ≥ +50% | 높음 | 입찰가 오설정, 예산 변경 | 일 단위 |
| R2 | 노출 급감 | 노출 변화율 ≤ -60% | 높음 | 소재 비승인, 중단, 비즈머니·결제 문제 | 일 단위 |
| R3 | CTR 급락 | CTR 변화율 ≤ -30% 그리고 기준일 노출 ≥ 3,000 | 보통 | 소재 피로, 매칭 변경, 순위 하락 | 일 단위 |
| R4 | 전환 0 | 당일 비용 ≥ 100,000 그리고 전환 0 그리고 기준일 전환 ≥ 1 | 긴급 | 전환 추적 태그 오류 | 일 단위 |
| R5 | CPA/ROAS 이탈 | 리드형: CPA ≥ 기준 +30% / 이커머스형: ROAS ≤ 기준 ×0.7 | 보통 | 입찰 전략, 시즌성 | 일 단위 (목표값은 설정) |
| R6 | 클릭 급증 | 클릭 변화율 ≥ +200% 그리고 전환 변화율 ≤ +20% | 높음 | 부정 클릭 | 일 단위 |
| R7 | 예산 조기 소진 | 일예산 소진 시각이 비정상적으로 빠름 | 높음 | 입찰 과다 | 시간대 데이터 필요 (2단계) |
| R8 | 비즈머니 부족 | 잔액 < 기준 | 긴급 | 충전 누락 | 잔액 데이터 필요 (2단계) |

**구현 범위**: 1단계는 R1~R6. R7·R8은 규칙 정의와 설정 화면 자리만 만들고, 데이터가 들어오면 평가하도록 확장한다. 임계값은 코드에 하드코딩하지 않고 설정으로 분리한다.

### 3. MVP 이후 기능 (제외)

- 광고 매체 API 자동 수집
- R7·R8 실제 평가 (시간대·잔액 데이터 수집, 2단계)
- 이메일·슬랙 등 알림 발송
- 로그인·회원가입 등 사용자 인증, 권한 구분, 프로필·설정 관리
- 이슈 담당자 지정, 댓글 협업
- 리포트 내보내기, 고급 차트·분석
