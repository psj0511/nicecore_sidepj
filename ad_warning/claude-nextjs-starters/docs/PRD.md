# 광고 성과 이상 감지 및 운영 이슈 자동화 시스템 MVP PRD

## 🎯 핵심 정보

**목적**: 광고 성과 데이터에서 이상 징후를 자동으로 찾아 이슈로 등록하고, Notion 티켓으로 넘겨 대응 누락을 막는다.
**사용자**: 광고 성과를 매일 점검하는 퍼포먼스 마케팅 운영 담당자와 팀장

**데이터 소스 원칙**: 성과 분석 대상은 **Notion에 올린 CSV(= Notion 데이터베이스)뿐**이다. 앱에서 CSV 파일을 직접 업로드하지 않는다. 담당자는 광고 성과 CSV를 Notion 지정 부모 페이지에 가져오기(Import)하고, 앱은 그 부모 페이지 하위의 데이터베이스를 읽어 분석한다.

**실시간 연동 원칙**: 성과 데이터는 앱으로 **복사·저장하지 않는다**(동기화 없음). 화면을 열 때마다 Notion 데이터베이스를 직접 조회하며, 호출 부담을 줄이기 위해 짧은 캐시(2분)를 두고 "지금 새로고침"으로 즉시 다시 읽을 수 있다. Notion에서 값을 고치면 다음 조회부터 바로 반영된다.

**데이터 저장 원칙**: 앱 전용 데이터베이스(Supabase 등)는 쓰지 않는다. 앱이 만든 데이터(감지 규칙, 이슈)도 **Notion 단일 저장소**에 둔다. 부모 페이지 하위에 `[AD] 감지 규칙`, `[AD] 이슈` 데이터베이스를 자동 생성하며, 성과 데이터베이스 탐색에서는 제외한다. Notion 토큰·부모 페이지 ID·티켓 데이터베이스 ID는 환경 변수(`NOTION_TOKEN`, `NOTION_PARENT_PAGE_ID`, `NOTION_DATABASE_ID`)로만 받는다.

## 🚶 사용자 여정

```
0. (사전) Notion 작업
   광고 성과 CSV를 Notion 부모 페이지에 가져오기 → 부모 페이지에 Integration 연결

1. 대시보드 페이지
   ↓ 열 때마다 Notion 성과 데이터를 실시간 조회 → 활성 규칙으로 이상 감지 → 새 이슈 생성
   ↓ 데이터가 없거나 오류가 있으면 "데이터 연결 상태" 메뉴 선택

2. 데이터 연결 상태 페이지
   ↓ 부모 페이지 하위 데이터베이스 목록·행 수·검증 오류 확인 ("지금 새로고침"으로 즉시 재조회)

   [Notion 미연동] → Notion 연동 설정 페이지 → 데이터 연결 상태 페이지로 복귀
   [검증 실패] → 데이터베이스·오류 행 안내 → Notion에서 수정하면 다음 조회부터 반영
   [정상] → 대시보드 페이지에서 감지 결과 확인
   ↓

3. 이슈 목록 페이지
   ↓ 이슈 선택

4. 이슈 상세 페이지
   ↓ 상태 변경 / "Notion 티켓 생성"

   [Notion 미연동] → Notion 연동 설정 페이지 → 이슈 상세 페이지로 복귀
   [Notion 연동됨] → 티켓 생성 완료, 티켓 링크 표시

5. 감지 규칙 관리 페이지 (필요 시)
   ↓ 규칙별 임계값 수정·활성/비활성 (R1~R6 적용, R7·R8은 자리만) → 다음 조회부터 바로 적용
```

### 2. 감지 규칙 정의

**공통 원칙**

- 비교 기준: 데이터 7일 미만이면 전일, 7일 이상이면 직전 7일 평균
- 최소 규모 필터: 기준일 비용이 100,000원 미만인 대상은 평가 제외
- 평가 단위: 구글 = 캠페인, 네이버 = 광고그룹
- 중복 방지: 동일 (규칙, 대상, 날짜)는 이슈 1건만 생성 (감지 키)
- 주말·공휴일 완화: 대상일이 주말·공휴일이면 R5와 전환 감소 계열은 심각도를 한 단계 낮추고 "주말·공휴일 가능성" 안내를 붙임

**규칙 목록**

| ID  | 유형           | 조건                                                     | 심각도 | 의심 원인                             | 지원                       |
| --- | -------------- | -------------------------------------------------------- | ------ | ------------------------------------- | -------------------------- |
| R1  | 비용 급증      | 비용 변화율 ≥ +50%                                       | 높음   | 입찰가 오설정, 예산 변경              | 일 단위                    |
| R2  | 노출 급감      | 노출 변화율 ≤ -60%                                       | 높음   | 소재 비승인, 중단, 비즈머니·결제 문제 | 일 단위                    |
| R3  | CTR 급락       | CTR 변화율 ≤ -30% 그리고 기준일 노출 ≥ 3,000             | 보통   | 소재 피로, 매칭 변경, 순위 하락       | 일 단위                    |
| R4  | 전환 0         | 당일 비용 ≥ 100,000 그리고 전환 0 그리고 기준일 전환 ≥ 1 | 긴급   | 전환 추적 태그 오류                   | 일 단위                    |
| R5  | CPA/ROAS 이탈  | 리드형: CPA ≥ 기준 +30% / 이커머스형: ROAS ≤ 기준 ×0.7   | 보통   | 입찰 전략, 시즌성                     | 일 단위 (목표값은 설정)    |
| R6  | 클릭 급증      | 클릭 변화율 ≥ +200% 그리고 전환 변화율 ≤ +20%            | 높음   | 부정 클릭                             | 일 단위                    |
| R7  | 예산 조기 소진 | 일예산 소진 시각이 비정상적으로 빠름                     | 높음   | 입찰 과다                             | 시간대 데이터 필요 (2단계) |
| R8  | 비즈머니 부족  | 잔액 < 기준                                              | 긴급   | 충전 누락                             | 잔액 데이터 필요 (2단계)   |

**구현 범위**: 1단계는 R1~R6. R7·R8은 규칙 정의와 설정 화면 자리만 만들고, 데이터가 들어오면 평가하도록 확장한다. 임계값은 코드에 하드코딩하지 않고 설정으로 분리한다.

### 3. MVP 이후 기능 (제외)

- 앱 내 CSV 직접 업로드 (성과 데이터는 Notion에 올린 CSV만 분석)
- 화면을 열지 않아도 자동 감지 (Notion 웹훅·주기 실행, MVP는 조회 시점 감지)
- 광고 매체 API 자동 수집
- R7·R8 실제 평가 (시간대·잔액 데이터 수집, 2단계)
- 이메일·슬랙 등 알림 발송
- 로그인·회원가입 등 사용자 인증, 권한 구분, 프로필·설정 관리
- 이슈 담당자 지정, 댓글 협업
- 리포트 내보내기, 고급 차트·분석

## 🗄️ 데이터 모델

**저장 위치**: 앱이 저장하는 데이터는 모두 Notion에 있다. 규칙과 이슈는 부모 페이지 하위 `[AD] 감지 규칙`, `[AD] 이슈` 데이터베이스에, 성과 지표는 사용자가 가져온 원본 Notion 데이터베이스에 있다. 별도 DB는 없다.

- **AdMetric** _(저장하지 않는 조회 모델)_: id(Notion 페이지 ID), source_id(원본 Notion 데이터베이스 ID), date, channel(구글/네이버), campaign, ad_group, spend, impressions, clicks, conversions, revenue. 조회할 때마다 원본 데이터베이스에서 읽어 검증 후 만든다
- **DetectionRule** _(`[AD] 감지 규칙` DB)_: id(Notion 페이지 ID), rule_code(R1~R8), type, severity, threshold(JSON 텍스트), target_value(R5 목표 CPA/ROAS), target_type, is_active, stage(1/2). R1~R8 기본값은 최초 접속 시 자동 생성
- **Issue** _(`[AD] 이슈` DB)_: id(Notion 페이지 ID), rule_id, source_id, target(캠페인 또는 광고그룹), target_date, detection_key(규칙+대상+날짜, 중복 방지: 생성 전 기존 키 조회), severity, status, baseline_value, actual_value, weekend_note, memo, detected_at, notion_url
- **Notion 연동 정보**: 토큰·부모 페이지 ID·티켓 데이터베이스 ID는 DB에 저장하지 않고 환경 변수로만 받는다

> **Notion 성과 데이터베이스 속성**: 날짜, 채널, 캠페인, 광고그룹, 광고비, 노출, 클릭, 전환, 매출 (CSV 헤더가 그대로 속성명이 되므로 이 이름과 일치해야 함. 매핑 상수는 한 곳에서 정의)
